# Planes de pruebas

- [Repetir pedido](TEST_REPEAT_PEDIDO.md): escenarios funcionales previstos.

Los planes describen escenarios, no resultados ejecutados. Registrar salida real, fecha, entorno y evidencia en el módulo correspondiente antes de declararlos aprobados.

**[Protocolo obligatorio de navegadores automatizados](PROTOCOLO_NAVEGADORES.md):** headless por defecto; `finally`/teardown y verificación de cierre de páginas, contextos, navegador, procesos y temporales propios, incluso cuando falle la prueba. Todos los chats deben cumplirlo.
